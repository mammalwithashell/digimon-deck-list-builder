## Detailed Findings

### Issue 1: [FIXED] Empty evo_costs for BT16-BT25 sets prevented all digivolution
- **Card(s)**: ALL Medusa Digimon (BT21-*, BT24-*, P-189)
- **Severity**: critical
- **Category**: digivolution
- **Expected**: Digimon should have evo_costs populated from card data so digivolve actions appear.
- **Actual**: cards.json had empty `evo_costs: []` for all BT16+ sets because the DigimonCard.io API returns `evolution_color: null` and `evolution_level: null` for newer sets, and `parse_evo_costs()` required all three fields to be non-null.
- **Fix Applied**: Updated `tools/ingest_cards.py` to infer missing `evolution_color` (from card's own color) and `evolution_level` (from card's level - 1). Re-ingested BT16, BT18, BT21, BT22, BT23, BT24, P sets. Manually fixed BT24-012 (API returned null for all evo fields).
- **Status**: FIXED

### Issue 2 (SYSTEMATIC): Effects fire at every timing -- causes memory corruption
- **Card(s)**: ALL tamer/option field effects -- BT18-087, BT21-081, BT24-082 Owen Dreadnought, P-035 Red Memory Boost, P-103 Offense Training, LM-027 Red Scramble, BT24-089 Unique Emblem
- **Severity**: critical
- **Category**: effect
- **Expected**: Effects should only fire at their designated timings.
- **Actual**: Effects fire at OnTappedAnyone, OnAllyAttack, OnSecurityCheck, OnLoseSecurity, OnEndAttack, OnAddDigivolutionCards, OnAddHand, OnUseOption, OnEnterFieldAnyone, OnEndMainPhase, OnAddSecurity -- literally every timing the engine checks. **This causes memory corruption**: P-035's Delay "Gain 2 memory" fires multiple times per action, resulting in memory increasing instead of decreasing (e.g., digivolving at cost 3 changed memory from 10 to 14).
- **Root Cause**: Engine `_effect_matches_timing()` returns `True` for unflagged effects. `ICardEffect` only has 4 timing flags; all other timings (OnStartMainPhase, OnEndTurn, OnTappedAnyone, etc.) have no flag and fall through.
- **Impact**: Memory accounting is unreliable whenever Delay/memory-gain effects are on the field. This is the most severe bug.

### Issue 3: BT24-018 Styracomon alt digivolve condition is wrong
- **Card(s)**: BT24-018 -- Styracomon
- **Severity**: high
- **Category**: digivolution
- **Expected**: Alt digivolve condition is "While you have [Owen Dreadnought], [Lamiamon]: Cost 6" -- meaning you can digivolve from Lamiamon for cost 6 when Owen Dreadnought is anywhere on the field.
- **Actual**: Script sets `_alt_digi_name = "Owen Dreadnought"` which makes `_check_alt_digivolve()` check if the base permanent contains "Owen Dreadnought" in its name. This incorrectly allows digivolving ONTO Owen Dreadnought (a Tamer!) instead of checking that Owen exists on the field.
- **Evidence**: Action 506 "Digivolve Styracomon onto Owen Dreadnought" appears in action list

### Issue 4: BT21-008 Elizamon On Play spurious trash pop
- **Card(s)**: BT21-008 -- Elizamon
- **Severity**: high
- **Category**: effect
- **Expected**: On Play should only reveal top 3 cards and select from them.
- **Actual**: Script `process0` pops a card from trash and adds to hand before the reveal-and-select. Same transpiler artifact as BT23-048 Gotsumon.

### Issue 5: P-035 Red Memory Boost spurious trash pop + memory anomaly
- **Card(s)**: P-035 -- Red Memory Boost!
- **Severity**: high
- **Category**: effect
- **Expected**: Reveal top 4 of deck, add 1 red Digimon to hand, rest to deck bottom. Cost: 3.
- **Actual**: Script pops from `player.trash_cards` before the reveal-and-select. Memory changed from 10 to 11 after playing (should be 10 to 7 for cost 3). The +4 discrepancy is from spurious trash pop + systematic timing bug causing memory effects to fire.
- **Evidence**: Memory: 10 -> 11 after playing cost-3 option

## Root Cause Analysis: Systematic Effect Timing Bug

See CS Hudiemon report for full analysis. The bug in `_effect_matches_timing()` is the same. For the Medusa deck specifically, it causes:
1. P-035 Red Memory Boost Delay "Gain 2 memory" fires at OnAddDigivolutionCards, OnAddHand, OnAddSecurity -- giving +2 memory each time
2. BT18-087 Owen's "security loss delete" effect fires at every timing
3. BT21-081 Owen's "Start of Main Phase: gain 1 memory" fires at OnEnterFieldAnyone
4. Net effect: memory accounting is unreliable whenever these cards are on the field
