## Detailed Findings

### Issue 1: EX11-012 Medusamon cannot digivolve onto BT24-016 Lamiamon
- **Card(s)**: EX11-012 Medusamon
- **Severity**: high
- **Category**: digivolution
- **Expected**: EX11-012 (Lv.6 Red) should digivolve onto any Lv.5 Red Digimon for cost 3
- **Actual**: No digivolve action appears in mask; `evo_costs` array is empty in `cards.json`
- **Steps to Reproduce**:
  1. Create game with BT24-016 on P1's field and EX11-012 in P1's hand
  2. Check action mask for digivolve actions (400+)
  3. No digivolve action available
- **Evidence**: action mask shows only [0, 62], no 400+ actions
- **Root Cause**: `cards.json` line 69623 has `"evo_costs": []` for EX11-012
- **Fix**: Added `[{"card_color": 0, "level": 5, "memory_cost": 3}]` to EX11-012's evo_costs
- **Status**: FIXED and verified — action 400 now appears in mask

### Issue 2: Digimon can attack suspended Tamers
- **Card(s)**: Engine-level (game.py)
- **Severity**: high
- **Category**: game_flow
- **Expected**: Only suspended Digimon should be valid attack targets (per official rules)
- **Actual**: `game.py:1686` sets attack mask bit for any `target.is_suspended` without checking `target.is_digimon`; Tamers in battle_area can also be suspended
- **Steps to Reproduce**: Code inspection — line 1686 and 1759 in game.py
- **Root Cause**: Missing `and target.is_digimon` in two attack mask checks
- **Fix**: Added `and target.is_digimon` to both lines (1686 and 1759)
- **Status**: FIXED (code fix applied; Raid path already correctly checks `target.is_digimon`)

### Issue 3: Petrification Tokens not implemented
- **Card(s)**: EX11-012 Medusamon, BT24-017 Medusamon
- **Severity**: medium
- **Category**: effect
- **Expected**: Medusamon effects should create Petrification Tokens (White/3000 DP Digimon with [Your Turn] can't suspend, [On Deletion] trash top security)
- **Actual**: Scripts contain `pass # descriptive-tagged: play_token` stubs; no `Game.effect_play_token()` exists
- **Root Cause**: Engine does not support token creation. Requires new `effect_play_token()` method, synthetic CardSource generation, and token property system
- **Status**: DOCUMENTED as engine limitation — not fixable without engine work

### Issue 4: Elizamon/Dimetromon OnLoseSecurity inherited adds memory to wrong player
- **Card(s)**: BT24-008 Elizamon, BT24-012 Dimetromon, BT21-008 Elizamon
- **Severity**: high
- **Category**: effect
- **Expected**: `[Your Turn] [Once Per Turn] When opponent's security removed, gain 1 memory` — card owner gains memory
- **Actual**: Memory is added to the player who LOST security (the opponent), not the card owner
- **Steps to Reproduce**:
  1. Build stack: Lamiamon > Dimetromon > Elizamon on P1's field
  2. Attack P2's security on P1's turn
  3. Memory before: 3, memory after: 1 (decreased by 2 instead of increasing by 2)
- **Evidence**: Logs show "OnLoseSecurity | Gain 1 memory" x2 but memory 3 → 1
- **Root Cause**: `game.py:478` — `context.update(extra_context)` overwrites `context["player"]` (the card owner) with `extra_context["player"]` (the player losing security, passed from `player.py:530`). The process callback uses `ctx.get('player')` which is now the wrong player.
- **Fix**: Changed process callbacks to use `card.owner` (closure variable) instead of `ctx.get('player')` in all 3 scripts
- **Status**: FIXED and verified — memory correctly increases from 3 to 5 (+2 from two inherited effects)

### Issue 5: BT24-016 Lamiamon WhenDigivolving requires another Reptile/Dragonkin (incorrect)
- **Card(s)**: BT24-016 Lamiamon
- **Severity**: high
- **Category**: effect
- **Expected**: `[When Digivolving] [When Attacking] [Once Per Turn]` effect fires on digivolve unconditionally
- **Actual**: Script `condition2` checks for another Reptile/Dragonkin on field (excluding self). Effect silently fails when Lamiamon is the only Digimon.
- **Steps to Reproduce**:
  1. Digivolve Lamiamon as solo Digimon (no other allies)
  2. WhenDigivolving does not fire — P2 hand/security unchanged
  3. With another Reptile on field, WhenDigivolving fires correctly
- **Evidence**: Solo digivolve: P2 hand 5→5, security 5→5 (no effect). With ally: P2 hand 5→4, security 5→5 (effect fired)
- **Root Cause**: Script condition incorrectly requires another Reptile/Dragonkin permanent. The card text has no such restriction for the WhenDigivolving/WhenAttacking effect.
- **Fix**: Simplified `condition2` to only check `card.permanent_of_this_card() is not None`
- **Status**: FIXED and verified — WhenDigivolving now fires even as solo Digimon

## Systemic Issue Noted

The `context.update(extra_context)` pattern in `game.py:478` is a systemic risk. Any `_fire_timing()` call in `player.py` that passes `"player": self` will overwrite the effect owner in the context. Other scripts using `ctx.get('player')` in OnLoseSecurity (or similar event-triggered timings) may have the same bug. Consider renaming the extra_context key to `"event_player"` to avoid collisions.
