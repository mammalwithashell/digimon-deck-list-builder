# PR 747 CI repairs

The failing head was `b03efa7f6` on `codex/search-batching-meta-evaluation`.
The three failing jobs were clone safety (three archetype tests), rules
conformance (three Option-placement observer tests), and exam simulation
(75 failures among 1,171 scenarios). The earlier engine library, both-path
card suites, DSL suite, semantic canaries, and Windows/Linux scheduler checks
had passed on GitHub.

## Source-selection resolver

The real shared defect was identity resolution for a live digivolution-source
pick inside a replacement continuation. The resolver scanned top-level
`RunTail` frames, although the active frame was nested in `ReplacementBody`.
It could not resolve the named source despite the action being legal. Seven
exam scenarios hit this defect.

`pending_material_source_carrier` now follows the existing active-frame
traversal through replacement/payment wrappers. It requires a live `Material`
prompt and its active material frame. It never borrows identities from an
older suspended frame, and reads the carrier's owner rather than inferring
ownership from the selecting player. The harness uses the same discriminator
for its `SelectCardEffect` wire classification. Source bounds, top-card
exclusion, occurrence ordering, and legality masks remain enforced.

Two new regressions failed before the repair: a nested replacement with an
opponent-owned carrier and a decoy on the selecting player's side; and an
inner non-material selection above an older material frame. Both pass after
the repair. Existing source identity/duplicate/bounds tests remain intact.

The opt-in `DIGIMON_EXAM_DEBUG_SNAPSHOT` diagnostic includes the live prompt,
candidate identities, trigger labels, and projection when an unfinished script
is rejected. It does not answer choices or permit unfinished scenarios.
The Python driver now reports ruling contradictions and unclassified process
failures instead of printing an empty error, and identifies the actual last
deck book whose error it reports. Three focused Python tests cover these
failure-reporting cases.

## Rust fixtures

  was widened.

## Exam scripts and assertion boundaries

The original 75 failing scenarios were reproduced locally before editing.
Seven pass through the shared resolver repair alone. The other 68 need script
or setup corrections:

- Remove obsolete simulator-only activation gates when there is no live
  prompt: target-starved DNA/evolution effects, and security-played Kyo's
  resolved self-trigger. A strict missing-prompt error remains an error.
- Explicitly answer simultaneous trigger order, reduced evolution cost,
  attack/hand-payment targets, optional inherited unsuspends, and deck-bottom
  order. Existing oracle-only decisions are retained; a few become shared
  where both engines now ask the same choice.
- Disambiguate interchangeable EX2-046 hand copies with a concrete hand slot.
- Correct two security seed orders by exchanging stack slots 5 and 9. The
  top security card is the last card dealt, slot 9. Both scenarios intended
  vanilla ST3-04, but had it at slot 5. The complete deck multisets and their
  expected battle/trash results are preserved.
- Move checkpoints past newly explicit choices so they still check the
  completed effect, including Examon's bottom-deck order and the two Q3399 /
  Q3401 inherited battle-win security trashes. Reindex nested ruling checks
  as well as top-level assertions. No assertion blocks are removed.

All 333 assertion blocks in the 68 edited scenarios are retained. One authored
expected value is corrected: ST23-11-effect2's intermediate
ST23-08 DP is 10,000, not 7,000. Printed ST23-08 grants its mandatory +3,000
before its optional source payment. This assertion has no oracle-backfilled
provenance; every other expected value is preserved.

The Gazimon optional-decline compatibility scenario retains its original
oracle decline and revealed cards. The simulator selects the optional
source-placement route, which has no eligible Three Musketeers-trait card
in that particular reveal, and returns all three. This checks the same
observable no-add/no-place outcome. The separate Rust archetype test checks
declining a pick with an eligible source.

## Validation and limits

All 75 original failures pass targeted replay after these repairs. The full
corpus then passes **1,171/1,171** scenarios (three local replay processes,
368.9 seconds). Option-flow passes **143/143**, including the new breeding
negative control. The Python failure-reporting tests pass **3/3**.

The local broad library run used release mode. Two pre-existing unconditional
`should_panic` tests require debug assertions (`debug_guard_rejects_mismatched_payload`
and `until_condition_rejects_missing_predicate_in_debug`), so they cannot pass
under that configuration. CI uses debug mode; no assertions were relaxed or
tests skipped to conceal this mismatch. The two new resolver regressions pass.

The mechanics-readiness, lowering-coverage, and card-admissibility freshness
checks pass without regenerating artifacts. Admission remains 1,036 of
4,476 registered cards; this patch does not promote cards or change verdicts.

No DCGO oracle session, backfill, or oracle-readiness promotion was performed.
Simulator-only replay verifies engine behavior against the retained expected
states; it is not fresh oracle confirmation. Search budgets, batching,
observation/action contracts, and models are unchanged. Training remains
`stopped_by_user`, with `auto_resume: false`; the pipeline-state SHA-256 remains
`74e8b53cc525d6307c959e0be364c04b82ccbdd9316ed477274b1d58e1608f7d`.
