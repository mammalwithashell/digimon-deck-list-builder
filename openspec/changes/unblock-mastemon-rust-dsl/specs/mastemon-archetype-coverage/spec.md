## ADDED Requirements

### Requirement: Resolved Mastemon pool is tracked
The system SHALL treat `qa/archetype-qa/mastemon-tribal/deck_pool.json`, generated by `code/tools/resolve_deck.py "Mastemon (Tribal)"`, as the coverage source for Mastemon archetype implementation.

#### Scenario: Pool resolves from deck library
- **WHEN** the Mastemon Tribal deck pool is resolved with the deck resolver
- **THEN** the output includes the resolved unique card IDs from `data/deck_library.json`
- **AND** `qa/archetype-qa/mastemon-tribal/deck_pool.json` is updated with those IDs

#### Scenario: Coverage accounting uses resolved pool
- **WHEN** Mastemon DSL coverage is reported
- **THEN** the report counts Rust YAML and behavioral tests against the resolved deck pool
- **AND** the report distinguishes Rust YAML coverage from legacy Python frozen-script coverage

### Requirement: Mastemon best deck has faithful Rust DSL coverage
The resolved Mastemon best deck SHALL have faithful Rust DSL YAML and behavioral tests for every unique card needed to run the deck without no-op stubs, hidden auto-selections, raw-Rust escapes, or approximated card text.

#### Scenario: Best-deck YAML exists
- **WHEN** the resolved best deck is enumerated
- **THEN** every unique card in that deck has `code/digimon-engine/cards/<set>/<CARD-ID>.yaml`
- **AND** each YAML file represents all printed main, inherited, security, and alternate-digivolution clauses from `data/cards.json`

#### Scenario: Best-deck tests exist
- **WHEN** the resolved best deck is enumerated
- **THEN** every unique card in that deck has a behavioral test under `code/digimon-engine/tests/cards_behavioral/<set>/`
- **AND** those tests exercise the card's gameplay-affecting printed clauses through `DebugRunner`

#### Scenario: Existing EX6-029 stub is completed
- **WHEN** `EX6-029 Mastemon` is reviewed after the change
- **THEN** its YAML implements the optional level 5 or lower Angel, Archangel, or Fallen Angel play from hand or trash
- **AND** its DNA-origin branch places one other Digimon at bottom security and trashes opponent security down to 4
- **AND** no printed effect body remains stubbed in comments

### Requirement: Mastemon boss line resolves faithfully
The core Mastemon boss line SHALL faithfully implement `EX6-029`, `P-187`, and `BT23-102` using Rust DSL and reusable substrate rather than raw-Rust card functions.

#### Scenario: EX6-029 Blast DNA and effect body
- **WHEN** `EX6-029` is used through Counter Blast DNA or normal play/digivolve
- **THEN** all printed legal decisions are exposed through pending selections
- **AND** the hand/trash play and DNA-origin security placement branch resolve according to printed text

#### Scenario: P-187 security placement and play branch
- **WHEN** `P-187` digivolves and has DNA origin
- **THEN** the player can choose another Digimon or Tamer, choose top or bottom security placement, and trash opponent security only if the placement succeeds
- **AND** its once-per-turn when-digivolving/when-attacking play branch requires trashing the player's top security before playing a valid yellow or purple Digimon with 6000 DP or less from hand or trash

#### Scenario: BT23-102 same-level and security-loss branches
- **WHEN** `BT23-102` digivolves with two or more same-level cards in its stack
- **THEN** both players trash security until they have 3 security cards
- **AND** its all-turns once-per-turn security-loss trigger can place a selected Digimon as bottom security through normal pending-selection flow

### Requirement: High-frequency Mastemon support core is implemented
The high-frequency Mastemon support cards SHALL be implemented and tested after the boss-line substrate lands.

#### Scenario: Support core has YAML and tests
- **WHEN** the change is complete for best-deck readiness
- **THEN** `BT14-033`, `ST10-04`, `EX6-020`, `BT23-031`, `BT23-067`, `BT11-042`, `BT11-083`, `BT11-094`, `EX6-074`, `BT15-037`, `EX6-022`, `BT9-082`, and `BT7-107` have production YAML and behavioral tests

#### Scenario: Support cards preserve visible choices
- **WHEN** a support card asks the player to search security, choose a hand/trash card, choose top or bottom placement, or DNA digivolve at end of turn
- **THEN** every legal choice is surfaced through the engine action mask or pending-selection mechanism
- **AND** no choice is auto-selected by the card implementation

### Requirement: Mastemon implementation does not alter active RL contracts
Mastemon card coverage SHALL NOT change active observation tensor contracts or `ACTION_SPACE_SIZE`.

#### Scenario: Action space is unchanged
- **WHEN** Mastemon substrate and card implementations are added
- **THEN** `digimon_engine.ACTION_SPACE_SIZE` remains unchanged
- **AND** new decisions reuse existing pending-selection action ranges

#### Scenario: Tensor profile is unchanged
- **WHEN** Mastemon substrate and card implementations are added
- **THEN** `standard_lite_v2` and `standard_compact_v1` tensor sizes and layout hashes are not changed by this card unlock work
