# Tasks — collapse DSL step idioms

> **Implementation note (verified 2026-06-18, before starting):** the field/zone select steps (`SelectHand`/`SelectTrash`/`SelectOwnPermanent`/`SelectOpponentPermanent`) ALREADY receive the dispatcher's *implicit* `tail` (the rest of the process body) at their execution sites in `code/digimon-engine/src/dsl_cards/step/selections.rs` (e.g. `install_select_hand(..., tail.to_vec(), ...)`), so `select_*` + a following step already works via the process sequence. The 8 existing `then:`-bearing structs (`SelectOwnSources`, `SelectOpponentSources`, `DigiBurst`, `SelectOpponentDpBudget`, `SelectOpponentPlayCostBudget`, `SelectOwnBreedingPermanent`, `SelectUnionArgs`, + 1) carry an EXPLICIT scoped `then` that the dispatcher must compose with the implicit tail. **The subtlety to get right:** when a field/zone select gains an explicit `then`, the explicit tail must run scoped to the selection binding AND compose correctly with the implicit dispatcher tail WITHOUT double-running — read how `SelectOwnSources` (selections.rs:645, compiled.rs:1653) threads its `then` into the install helper + `selection_result` and mirror exactly. This is the cloneable VM's `ResumeFrame::RunTail` data, so keep it closure-free. CompiledStep variants (`SelectOwnPermanent`/`SelectHand`/`SelectTrash`/`SelectOpponentPermanent`) need a new `then: Vec<CompiledStep>` field (`#[serde(default)]` for bincode-pack compat — see [[reference_dsl_substrate_authoring_gotchas]]; build.rs regenerates the pack via the build-dep on digimon-dsl).

## 2. `reveal_search` composite
- [x] 2.1 `add_to_hand_from_reveal` / `trash_from_reveal` / `return_to_deck_from_reveal` now move EVERY card in a `CardList` binding (new `resolved_cards` helper in `step/zone_moves.rs` replaces the `singleton_card` cap), so a bucket bound to a multi-card list adds/trashes/returns all of them — fixes the single-card limitation. (`singleton_card` is retained for the genuinely single-card arms.)
- [x] 2.2 Added `reveal_search { of, count, buckets: [{filter, to: hand|trash|deck, max, optional, prompt}...], remainder: top|bottom }` (`step.rs` spec + serde, `compiled.rs` `CompiledStep::RevealSearch` + helper enums, `compile.rs` lowering). It lowers to a single composite compiled step whose executor (`step/selections.rs` dispatcher) expands it at run time into the EXISTING sequence: `reveal_top_deck` → ONE `install_select_reveal_buckets` over all buckets (cross-bucket de-dup always on) → per-bucket reveal-move (§2.1) → `place_remainder_on_deck`, threading the outer tail. Reuses the existing reveal-bucket selection wholesale → parks/resumes identically; pure-data deterministic expansion (cloneable / reset-and-replay safe). A non-`optional` bucket forces `min = max` (the install advances when candidates exhaust → never soft-locks); `optional` → `min = 0`. **`remainder: choose` is DEFERRED to §3** (it needs §3.1's `StackPosition::Choice` player-elected placement; no migration target uses it). `to: deck` returns picks to the deck bottom.
- [x] 2.3 Corner cases in `tests/dsl/reveal_search.rs`: mandatory add-up-to-N (multi-card add), fewer-than-max (clamp, no soft-lock), short/empty pool (no match → nothing added, remainder returned), all-optional bucket declined via PASS, and two-bucket cross-`no_duplicate` routing to distinct destinations (hand + trash). Remainder ordering is exercised by every test (it resolves the inherited `place_remainder` ordering selection).
- [x] 2.4 Migrated **BT9-092** (Cool Boy — reveal 3, add 1 X-Antibody Digimon + 1 X-Antibody Option, bottom rest) to `reveal_search` as a real parity fixture; all 7 of its behavioral tests stay green (the end-to-end test drives via `auto_resolve`, so the select→bucketed-select flow change is transparent). **EX5-015 intentionally NOT migrated:** its "if you added cards, trash 1 from hand" follow-up needs the named bucket bindings (`pick_a`/`pick_b`) that `reveal_search` deliberately encapsulates — it correctly stays on the lower-level `select_reveal_buckets`. Broader mechanical migration of the ~55 longhand searchers is optional (back-compat keeps the longhand valid; proposal "no rewrite forced").
