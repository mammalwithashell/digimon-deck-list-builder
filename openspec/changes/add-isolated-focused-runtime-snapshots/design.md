## Goals / Non-Goals

**Goals:** Establish reproducible, source-derived execution for a finite deck/scenario/opponent closure; keep complete global membership and unresolved evidence visible; support new generation-bound measurement; ultimately admit only the tested bounded configuration to training.

**Non-Goals:** Global data publication, arbitrary meta/pool support, automatic correction acceptance, changing action/tensor layouts, promoting historical verdicts, or replacing independent behavioral review. Counts from a current audit are not contract constants.

## Decisions

### 1. Separate immutable artifact

Use a new producer-owned snapshot directory and schema, never `data/cards.json`, a publication candidate marker, or a committed global revision marker. A manifest binds schema, source aggregate and original observations, correction and selection documents, exact field approvals, registry, canonical producer closure, executable/evidence graph, pack, books, and consumer capability IDs. Seal content first and marker last, with atomic completion and before/after read checks. Publication commands explicitly reject this artifact type.

Global inventory is independently reconstructed from official, secondary, canonical, runtime and QA membership. Each member retains its classification and evaluated/blocked/unknown disposition. Stable registry indices and capacity remain globally owned; executable subsets do not renumber IDs. The full global candidate and its blockers stay separately reportable.

An alternative is to finish every global migration disagreement first. It avoids a new runtime profile but forces unrelated card review onto the focused campaign. The isolated route is justified only if the measured closure and strict consumer route are finite and reviewable.

### 2. Two explicit closure graphs

Executable closure E starts from the frozen target decks, exact opponents, every scenario setup zone and stack prefix, resolved named rest decks, and enabled variant/swap pools. Parse actual schemas and deck expansion rules, not card-ID regexes alone. Follow generated/named-card and token/template references through enabled implementation paths. Report unresolved or unbounded references as blockers.

Evidence closure Q retains complete shared Q&A memberships using both the row's member list and the denominator's reverse card-to-question association. Expand execution when scenarios/interactions require another member's behavior. Evidence-only members require complete semantics for their role; otherwise expand and review them or block. Every addition records its parent, reason and pinned source. Iterate to a fixed point. No member deletion may be used to close the graph.

### 3. Generate records from authority, then approve the consumer read set

Reuse pure canonical normalization, typed corrections, explicit source selection and forward projection against complete original inputs. Do not copy runtime rows from a blocked candidate or catch a global publication failure and use its partial output. Require byte equality with the normal producer for each admitted record.

Inventory the actual consumer read set: Rust CardData conversion and derived keywords; ordinary and Dual faces; Link, Rule grants, traits and identity; standard and alternate evolution/DigiXros paths; registry encoding; deck legality; and any enabled training features. Audit every represented field and conversion. Metadata not consumed by a selected capability must be explicitly classified and unavailable to that capability, not silently approved. Bind complete source containers including empty fields, repeated occurrences, alternate printings and retained disagreements.

### 4. Explicit verified runtime handle

The isolated entry point receives the snapshot explicitly and has no upward-search/default/fallback behavior. It verifies files, producer/consumer identities, closure, registry and pack before game construction, holds the verified immutable bytes, and rejects any outside-E lookup, deck, generated object or future variant before use. Tokens require a separately described reviewed template capability; synthetic defaults are not a substitute for missing source cards.

The actual repair-tree shared card store currently caches by a fingerprint that uses lengths for several text/cost fields and omits some structured metadata. Scoped execution must use a content/snapshot-bound store identity or a separate uncached verified store; passing a newly verified map into the existing cache alone is insufficient. Same-process tests must distinguish same-length text, evolution-cost, Dual and alias changes. This static audit finding needs a runtime regression before any shared engine fix is integrated.

On the repair branch, the embedded all-card DSL pack must be pinned and dispatch restricted to E; unrelated specs cannot acquire execution by registration alone. On later branches, preserve committed fixed-path build checks and specify a separately tested isolated pack route if needed. Do not patch a running build's inputs. Expose mismatches before dispatch and fail rather than silently switching profile.

### 5. Generation-bound evidence and staged consumers

Source-book v2 readers are initially offline and review-only. Activation requires a complete clause and gating-interaction book for the campaign, cross-language agreement, exact scenario binding, and append-only source-generation transition. Global unevaluated denominators remain unknown, never zero; the complete focused denominator must be known before measuring its readiness. Preserve all five existing verdict classes and raw historical evidence. Changed IDs, semantics, pack or source bindings make prior results stale; they never turn into fresh confirmations.

Required evaluation membership is E plus all Q roles requiring semantics. Derive exact clause IDs, bidirectional QA membership, structural obligations, versioned probe families and positive/negative cases, and promoted gating IDs independently of supplied books. Required unknowns or unclaimed gameplay fields block activation. Bind evidence to the full source/semantic/runtime/binary/pack/consumer/dependency/scenario/deck/interaction tuple. Transition only under the existing lock after STOP and verified claim/worker drain, with an exact predecessor comparison and idempotent staged successor activation. Preserve unresolved STARTED records, ancestor questions and cumulative accounting across crashes.

First enable only an isolated harness backend. Pilot and Architect follow after behavioral gates: exact decks, opponents, flex/swap pools, seeds/evaluation configurations and run/model metadata must bind the snapshot and observation/action/pack identities. Default registered pools remain unchanged. Training admission needs source validity, faithful implemented choices, current passing behavioral/oracle evidence, independent review and no active relevant blockers. A smoke game or greedy win alone proves neither fidelity nor policy quality.

## Risks / Trade-offs

- Closure growth or unknown dynamic references → retain the full graph and block that capability; reassess whether global repair is cheaper.
- A subset hides denominator members → independently derive the global inventory and shared interaction membership; compare both directions and reject omissions.
- Python/Rust parsing, default or keyword drift → shared actual fixtures, exact producer output checks and cross-language negative controls.
- Mixed files or changing dependencies → immutable marker-owned artifact, whole dependency closure hashes and read/dispatch epoch checks.
- Repair/base branch drift → record actual file hashes and behavior separately; re-review integration against destination contracts.
- Additional architecture delays deck fixes → stage small independently reviewed units; continue existing source and engine repair without duplicating global work.

## Migration Plan

   Compare destination specs and actual functions before implementation; if an existing default, fixed-path, producer bootstrap, pool or training contract changes, add its exact OpenSpec delta before changing it. New capability naming does not waive existing contracts.
2. Implement only offline producer/validation under TDD, including publication refusal and adversarial closure/race cases. Update corresponding pipeline/pool documentation.
3. Implement the explicit isolated harness handle and dispatch guards; keep all current lane STOP files until exact generation validation succeeds.
4. Integrate coherent v2 clause, interaction, scenario and verdict generation handling. Revalidate preserved engine fixes on separate branches and integrate reviewed changes only into isolated campaign branches.
5. Resume one existing worker per lane through saved process-local launch specs after actual process/branch/ledger checks. Keep cumulative usage and immutable old generations.
6. Add and validate the bounded training consumer contract and update training/runtime documentation. Admit the exact deck configuration only after all stated gates pass.

Rollback selects the previous immutable handle/generation after draining with STOP. Never rewrite historical evidence, kill workers, or install the scoped artifact into global paths.
