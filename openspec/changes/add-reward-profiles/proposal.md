## Why

`DigimonEnv._compute_reward` hardcodes a single reward recipe in `code/digimon_gym/digimon_gym.py` (lines 389–483), with shaping knobs (`digivolve_reward`, `dna_digivolve_bonus`, security weights, fast-win bonus) scattered as flat fields on `TrainingConfig`. Every archetype the agent pilots gets the same teaching signal even though aggro, control, and combo decks have fundamentally different win conditions. There is no way to swap reward shapes between runs, no way to teach the agent that DNA digivolving matters for DNA Omnimon but not for Rocks, and no per-component telemetry — only an aggregate `pilot/mean_eval_reward` scalar.

This change introduces composable reward components, YAML-defined reward profiles, agent-archetype-keyed profile assignment, and per-component telemetry. It also wires three Rust engine events (`Attack`, `Trash`, `SecurityReveal`) that exist as `GameEvent` variants but are not yet emitted, unlocking block / deletion / security-reveal components.

## What Changes

- **New** `RewardEventBus` in `DigimonEnv`: drains `get_rl_state` counter deltas and engine `drain_events()` into a normalized stream of typed `Occurrence` records (`PlayedCard`, `Digivolved`, `DnaDigivolved`, `Blocked`, `OppDeleted`, `SecurityRemoved`, `TerminalOutcome`, etc.). Occurrences carry **arrival-aware** fields: `PlayedCard` includes `cost_paid` and `cost_printed`; `Digivolved`/`DnaDigivolved` include `result_card_id`, `result_traits`, `result_level`, `was_dna`, and `was_blast_dna` so components can distinguish "DNA into Omnimon" from "hardcast Omnimon at full cost."
- **New** `RewardComponent` protocol and registry under `code/digimon_gym/agents/reward/`: each component is a small class with `name` and `compute(occurrences, episode_state) -> float`. v1 ships 12 components, including a new `digivolve_into_named_card` that mirrors `play_named_card` semantics on the digivolve side.
- **New** `RewardProfileWrapper` (wrapper-chain position: between `DigimonEnv` and `OpponentWrapper`): resolves the active profile by reading `info["deck1_archetype"]` from the deck-pool wrapper, sums weighted component contributions subject to per-component and per-profile budgets, replaces the env's scalar reward, and writes `info["reward_breakdown"]` and `info["reward_profile"]`.
- **New** `code/digimon_gym/agents/reward/profiles.yaml`: defines named profiles with optional `inherits`, optional profile-level `budget:` block (`per_episode_cap`, `per_episode_floor`), per-component `budget:` keys (`max_fires_per_episode`, `max_total_per_episode`, `diminishing_returns_factor`), an optional `key_cards:` block that declaratively expands into reward / hardcast-penalty / alt-path-bonus components plus populates the boss-cards telemetry set, plus a top-level `assignments` map (`archetype_name -> profile_name`) including a required `_default` profile. The shipped YAML includes `dna_omnimon_combo_v1` and `bg_imperialdramon_combo_v1` profiles using `key_cards:` with the actual card IDs (BT17-078, AD1-025, BT17-081, BT22-017 for DNA Omnimon; BT16-085, BT12 Stingmon/ExVeemon/Paildramon for BG Imperialdramon).
- **New** hot-reload of `profiles.yaml`: the loader stat()s the file at every `env.reset()` and re-parses when mtime advances. The active profile for each episode is locked at `reset()` time; mid-episode edits never apply mid-game. The per-game sidecar row records the profile hash actually used so reproducibility survives reloads.
- **New** TrainingConfig fields: `reward_profiles_path` (default `code/digimon_gym/agents/reward/profiles.yaml`), `reward_profile_override` (single profile for non-generalist runs), `reward_profiles_hot_reload` (default `True`). Today's flat `digivolve_reward` / `dna_digivolve_bonus` fields are retained as DEPRECATED no-ops in v1, with a `DeprecationWarning` directing users to profiles; removal deferred to v2.
- **New** per-component TensorBoard scalars `pilot/reward/<component>/mean_per_game` and per-profile aggregates `pilot/profile/<profile_name>/mean_reward`, `pilot/profile/<profile_name>/share_<component>`. Per-archetype × component breakdown lands in the `evals.jsonl` sidecar (not TB).
- **New** per-game eval columns surfacing arrival-aware metrics: `digivolves_into_boss_agent`, `digivolves_into_boss_dna_agent`, `hardcasts_of_boss_agent`, `hardcasts_of_boss_full_cost_agent`, `digivolve_discipline_agent` (= digivolves / (digivolves + hardcasts)). "Boss cards" derive from each profile's `digivolve_into_named_card` entries whose reward weight ≥ `BOSS_REWARD_THRESHOLD` (default 2.0, overridable per profile via metadata).
- **New** `reward_profile_name` and `reward_profiles_hash` in `models/<run>/metadata.json`, parallel to `tensor_profile` / `tensor_layout_hash`. Mismatched profile hash on resume raises a clear error (overridable with a flag). When hot-reload is active, additional per-episode hashes are recorded in the sidecar `evals.jsonl`.
- **Modified** Rust engine `code/digimon-engine/src/game.rs` and `events.rs`: emit `GameEvent::Attack`, `GameEvent::Trash`, and `GameEvent::SecurityReveal` at their existing wiring points (variants already exist but emission is TODO per the file's own comment). Additionally **extend** `GameEvent::Play` with `cost_paid: i16`, `cost_printed: i16`, and `via_alt_path: Option<String>`; **extend** `GameEvent::Digivolve` with `was_dna: bool`, `was_blast_dna: bool`, `memory_paid: i16`. Field additions are non-breaking for existing event consumers because the variants serialize via `#[serde(tag = "type")]`.
- **Modified** `WinRateCallback` to aggregate per-component, per-profile, and per-(agent_archetype, component) tallies from `info["reward_breakdown"]`, following the precedent of `_archetype_*` / `_agent_archetype_*` dicts from `per-archetype-digivolve-telemetry`. Also accumulates the new arrival-aware counters for the boss-arrival sidecar columns.
- The shipped `_default` profile encodes today's recipe byte-identical — existing runs without explicit profile selection produce the same reward signal they do today.

## Capabilities

### New Capabilities

- `reward-profiles`: composable reward components (including arrival-aware `digivolve_into_named_card` and cost-aware `play_named_card`), named profiles in YAML with per-component and per-profile budgets, per-agent-archetype profile assignment, hot-reload on file change, per-component and per-profile telemetry, boss-arrival eval-column drilldown, run-metadata persistence with hash verification.
- `engine-event-emission`: emission of the `Attack`, `Trash`, and `SecurityReveal` event variants from the Rust engine at their existing call sites, AND field extensions to the already-emitted `Play` and `Digivolve` variants. Covers the event surface required by `reward-profiles` v1 components (`block_event`, `opp_deletion`, `own_deletion`, `digivolve_into_named_card`, cost-aware `play_named_card`) and is independently useful for replay/UI consumers.

### Modified Capabilities

- None. `per-archetype-digivolve-telemetry` continues to function unchanged (its callback fields are independent of the new reward-breakdown aggregation). The `digivolve_shaping` config path becomes a deprecated alias for selecting a digivolve-shaped profile, but its on-disk behavior (asymmetric agent-only) is preserved.

## Impact

- **Affected code (Python)**: `code/digimon_gym/digimon_gym.py` (env emits occurrences alongside reward), `code/digimon_gym/agents/pilot_training.py` (wrapper insertion, callback aggregation, metadata write, boss-arrival columns in evals.jsonl), `code/digimon_gym/agents/training_config.py` (new fields, deprecation warnings), new package `code/digimon_gym/agents/reward/` (components, registry, profile loader with hot-reload, wrapper, budget engine).
- **Affected code (Rust)**: `code/digimon-engine/src/events.rs` (field additions to `Play` and `Digivolve` variants), `code/digimon-engine/src/game.rs` and `game_actions.rs` (event emission at attack declaration, trash migration, security reveal; extended payload at `Play` / `Digivolve` emit sites including cost_paid, cost_printed, was_dna, was_blast_dna, memory_paid), new integration tests under `code/digimon-engine/tests/event_emission/`.
- **Affected data**: new `code/digimon_gym/agents/reward/profiles.yaml` shipped in-repo with `_default`, `_digivolve_shaped`, `dna_omnimon_combo_v1`, and `bg_imperialdramon_combo_v1` profiles. No changes to `data/cards.json`, deck library, or tested-cards.
- **Affected configs**: `TrainingConfig` gains three fields and two deprecation warnings. Existing YAML run configs that omit reward fields are unaffected (default profile is byte-identical to today).
- **Affected docs**: new `docs/REWARD_PROFILES.md` (component catalog, YAML schema, budget knobs, hot-reload semantics, telemetry reference, archetype-profile authoring guide); updates to `docs/TRAINING_RUNBOOK.md` (one section on selecting profiles); cross-link from `docs/RUST_ENGINE_API.md` event-emission section.
- **Out of scope (deferred)**: `ModifierApplied` engine event and `apply_status_*` components (cannot_attack / no_blocking / no_digivolve); opponent-archetype-keyed profiles; matchup (N×N) profiles; cross-profile reward normalization; TB-tier per-(archetype × component) scalars; per-set play_plan archetype profiles beyond the two shipped DNA examples. These get follow-up proposals.
- **No breaking changes** to the public action space, observation tensor, replay format, or saved checkpoints. Existing trained models load and evaluate identically. The `Play` / `Digivolve` event field additions are serialized via `#[serde(tag = "type")]` and remain backward-readable for consumers that ignore unknown keys.
