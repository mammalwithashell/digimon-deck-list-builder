# Queued captured-context repair: guarded invocation prototype

Status: implementation preparation, not an admitted projection or scored runtime.
Human authorization permits fixing, qualifying and separately retrying both failed
closed panels. Historical attempts and frozen claims remain immutable.

## Why a clause-only certificate is insufficient

The model-free 108-action replay reaches an older queued BT24-003 context whose
security-to-hand anonymous token lost membership after a public hand departure.
The real queued Shaman resolution can reach a BeforePayCost callback that reads
that captured event reference. Removing it changes payment by one memory in the
saved synthetic counterexample. Current field-only inspection cannot prove that
no such callback will be present later: earlier pending and queued effects can
change the field before the observer activates.

## Proposed boundary

An invocation-time obligation travels with the captured context, through clones,
queued entries, parked selections and outer continuations. Before invoking any
callback under that context, reject if independence from the projected reference
fields has not been proved. The rejection must precede the callback body. A
callback installed later receives the same check; a prior world-admission result
does not grant it permission. Ordinary unprojected contexts retain their behavior.

The guard remains deliberately unconnected to production admission. A private
TriggerContext marker carries the obligation. Registered CardEffect factories,
stored raw declarative factories and the common keyword factory wrap returned Effect callbacks through
`determinize/context_guard.rs`; cloned registries and cached callback Arcs retain
those checks. This guards invocation, not factory execution or opaque captures.
No production projector originates the marker. Every marked callback remains
unsupported; compiler certificates are not implemented.

## Obligations before enabling this in closed worlds

- Enumerate all Effect closure fields, including conditions/qualifiers, process,
  cost/payment/activation, dynamic modifiers, replacements and filter callbacks.
  Cover registry, direct keyword, granted, cached and refired effect construction.
- Cover callbacks outside Effect: modifier replacement and UntilCondition
  predicates, granted bodies, selection callbacks, runtime predicates, raw DSL
  formula/step registries and any native direct reader. Unknown surfaces reject.
- Prove marker propagation at every captured-context assignment, merge, clone,
  restoration and event-construction boundary. Creating a new event does not
  automatically justify discarding a dependency inherited from the old one.
- Distinguish direct independence from transitive calls in compiler facts.
  A literal evolution step is not a transitive certificate. Certify all branches
  and deferred tails, and keep unrecognized AST nodes and raw closures strict.
- Limit any eventual projection to exactly the reference fields covered by the
  proof. Keep cause, ownership, timing, entitled references and snapshots intact.
- Ensure callback rejection aborts the entire native request. It must not become
  a draw, fallback action, dropped rollout, successful receipt or resampled world.
- Prove late-reader, alternative-route, continuous-reader, replacement and parked
  cost cases, along with existing success/decline/OPT/outer-context/privacy tests.
- Reproduce the original failure point without removing queue entries. Freeze a
  complete new source/runtime pair and pass full reference qualification, exact
  parity and measured runtime profiles before fresh scored attempts.

No arbitrary opaque token, actual hidden handle, true hidden identity inspection,
queue removal, or weakened audit is authorized by this prototype. The existing
strict admission rejection remains in force while the obligations above are open.

## Source-review notes

The Effect surface has 16 closure fields; `outer_optional_guard` is a separate
reader and must not be omitted. The initial prototype's wider test matrix checks
it alongside the other fields. The static assignment inventory is a search aid,
not proof that all context transfers have been covered.

Existing certificates also require review. The historical `context_liveness.rs`
whitelist admitted named-target literal EffectInitiatedDigivolve steps. Naming the target does not
remove the transitive cost-callback dependency demonstrated by the saved synthetic
counterexample. No additional certificate should be admitted from syntax alone.

The reviewed panic-restoration scopes in combat, replacement and effect lifecycle
code resume unwinding after restoring temporary state. Search and the frozen
driver have no textual catch_unwind match. This bounded source review supports,
but does not replace, the required end-to-end rejected-request test.

## Captured and nested obligations

The external-callback prototype carries a bit-only CapturedReadObligation for
explicitly declared captures. It never stores a hidden card or payload. Invocation
checks both that captured obligation and the current context, including nested
simultaneous-play members. This matters for a selection that restores its own
captured context only after entering its body: a current-context-only check would
be too late to protect that restoration and subsequent reads.

This is not capture introspection. An obligation recorded before a later
projection cannot authorize opaque captures that the projector cannot rewrite.
Integration must reconstruct callbacks from audited structured data or reject
opaque captures, and must account for every captured context. The seven external
families presently represented are UntilCondition, passive replacement, granted
body, granted qualifier, runtime permanent predicate, selection and decline.
Their wrappers are not installed by production constructors or registries.

The remaining explicit surfaces include raw-security and source-completion
filters in owned_card_choice, PartitionRequirement.matches, raw DSL step/formula/
declarative factories, formula extension function pointers and native direct
readers. Passing wrapper unit tests is not evidence that these are covered.

## Unconditional certificate tightening

The new `closed_transitive_certificate` tests execute the named-target DSL
evolution itself: removing its event reference changes payment by one memory
through a BeforePayCost callback. A second test executes literal GainMemory;
the same erasure changes whether an UntilCondition DP modifier survives.
Both operations were accepted by the historical whole-clause predicate.

The syntax analysis is now named `direct_references_unused` and explicitly does
not authorize projection. `ignores_event_card_identity`, which drives production
admission, requires both those direct facts and an empty process body while the
transitive invocation mechanism remains unadmitted. Nonempty bodies cannot use
the old syntax whitelist to erase references.

This tightening may reject reference fixtures that previously passed. Keep their
positive coverage tests and original requests unchanged, record the failures,
and restore support only with a sound transitive proof. Do not count the focused
safety tests as full software or model qualification. The residual RunTail
certificate is separate and remains subject to its own environment guards.

## Raw dispatch integration

The first production dispatch checks are now placed on stored raw DSL step and
formula callbacks and on FormulaExtensionRegistry.evaluate. Checking when the
body is invoked, rather than when a callback is looked up, covers callbacks
retained before a marked context is restored and callbacks obtained from cloned
registries. Unknown names preserve their existing absent-entry behavior.

This is a bounded current-context check, including nested simultaneous contexts.
It does not infer opaque closure captures. Raw declarative factories receive a
CardHandle rather than a Game, so their construction and generated readers still
require a separate design. Effect/external wrappers are not installed, native
and structured readers remain incomplete, and no production projector sets the
marker. These three dispatch checks alone do not admit any projected world.

The old GainMemory syntax-only positive assertion and the new UntilCondition
counterexample cannot both justify an unconditional certificate. Preserve the
original test and its recorded failure. A future API migration must separate
direct syntax facts from complete execution safety and retain or strengthen
behavioral/privacy coverage; it must not claim the disproven unconditional
guarantee is safe merely to recover a green suite.

## Stored owned-choice and Partition dispatch

Stored raw security and source-completion filters now check the current context
inside their Arc wrappers. Source completion covers both recovery with no
candidate and eligibility with a candidate; cloning a choice retains the same
wrapped callback. The two engine Partition matching sites invoke a checked
matches_source method, including requirements built directly through the public
callback field. This does not claim that external direct use of that field is
guarded.

These checks do not cover filter calls made before the owned choice is stored.
In particular, select_security calls its filter while constructing the initial
candidate list. Source-multi, DP-budget, play-cost-budget and union selection
also have immediate or deferred raw filters. A bounded source review records
21 nearby filter call sites; that inventory is not semantic coverage. They need
a batch of invocation tests and checks before any projection is enabled.

Opaque captures with an unmarked current context remain unsupported. No new
context erasure or scored-world admission follows from these dispatch checks.

## Initial and deferred selection-filter dispatch

The selection module now checks current-context provenance immediately before
the reviewed filter invocations: initial zone/field/breeding/count-capped filters,
security search, source enumeration and prefix revalidation, DP and play-cost
budget candidates, and union card/carrier filters. The shared helper accepts a
deferred body so the check occurs before the user callback is evaluated. Nested
simultaneous contexts are checked by the existing recursive guard.

These are invocation checks, not a certificate about arbitrary captured state.
They do not cover selection result/decline callbacks, compiler/native direct
readers, raw declarative factories, or all structured resume paths. No projector
sets the marker. Sound capture/context-transfer handling and complete runtime
qualification remain prerequisites for any new scored attempt.

## Raw selection-result dispatch

Normal and payment-probe selection resolution share one dispatcher. After
legality and presentation-only navigation handling, raw accept/decline paths
check the current context before consuming the prompt, changing its phase, or
entering deferred-drain scopes. An impossible owned choice that invokes no raw
result body retains its recovery path. Illegal actions still return the existing
selection errors. This does not install the prototype capture wrappers or
inspect arbitrary closure captures.

Structured ResumeStack execution bypasses these raw result callbacks. Its saved
contexts, outer tails, post-selection hooks, and recovery cleanup need separate
audits before projection can be enabled. A check of the current context cannot
certify an unmarked caller whose closure restores an unaudited captured context.

## Modifier expiry and passive replacement dispatch

The three `ModifierRegistry::evaluate_until_condition` callback paths (permanent,
player, keyword) check the current context immediately before invoking an existing
predicate. Missing entries retain `None`. The permanent/player passive candidate
conditions in the replacement dispatcher check after timing/cause filtering and
before the callback. Directly assigned public callback fields use these same
engine paths; no constructor wrapper is assumed.

These are local invocation checks, not rollback of an entire modifier sweep or
proof of opaque captures. The two expressions previously inventoried in
`guard_carrier_can_be_deleted_for_cost` belong to a private unused helper: the
current source has no callers and the compiler confirms it is unused. That text
inventory did not establish an active reader path. Effect conditions, structured
continuations, capture/context transfers and compiler facts remain obligations.
No production projector sets the marker, and this work does not admit projection.

## Granted callback dispatch

Four actual invocation sites check the current context before calling unknown
granted code: the queued trigger qualifier, queued body, inline compatibility
body, and dynamic grant predicate. Queued paths check after installing their
queued context. Absent callbacks and timing mismatches retain their existing
results. Public-map insertion, late registration and cloned registries cannot
bypass checks at these engine invocation sites; arbitrary external invocation of
the public callback handles is not covered.

The qualifier's temporary context uses an RAII scope and is restored on rejection.
The queued body's outer attribution scope is not proved to roll back on panic.
Tests require rejection before callback execution and registry cleanup, not that
the rejected hypothetical state can be reused. Whole-request fail-closed behavior
remains required, as do opaque-capture and context-transfer proofs. Existing
prototype capture wrappers remain uninstalled; these checks do not authorize
projection or certify pre-callback native reads.

## Simultaneous queue context transfer

Queue qualifier probes and matching-member selection now copy the selected
member while retaining the boolean union of obligations anywhere in the original
group, including its parent, siblings and nested members. This conservative
propagation happens before a qualifier can short-circuit or a condition can
filter a member. Matching results retain the union for body selection and outer
optional-prompt consumers. The original queue entry and selected subject payload
remain unchanged; no additional hidden handle is retained to carry the obligation.

These queue tests cover those transfers only. The separate DSL transfer is
tracked below. The group-union rule does not establish callback safety,
opaque-capture safety, or whole-request abort. Projection remains disabled.

## DSL selected-subject scope

`WithSimultaneousPlaySubject` now uses the same boolean-union propagation when
installing its selected member. Its structured inner continuation captures that
member context when a choice parks. For a tail outside this subject scope,
`park_outer_tail` uses a typed `OuterContinuation` with the restored enclosing
context instead of the context-free ambient slot. The old ambient optimization
ran the enclosing tail inside the selected member context. Other control-flow
steps and the existing orphan fallback retain their representations.

The focused proof exercises synchronous raw callbacks and parked
`SelectEffectChoice`/`RunTail` clones, including both legal choices under an
unmarked caller, normal outer-context restoration and invalid binding/index
no-ops. It does not establish other resume variants, decline/recovery hooks,
opaque captures or projection after capture. Panic attribution rollback and
whole-request rejection remain separate requirements. No projector is enabled.


## Inactive world obligation for opaque captures

A private Game boolean now participates in the shared unknown-callback check.
It defaults false and its only setter is cfg(test): no production projector can
originate this world obligation. Derived Game cloning retains it independently
in the clone. Replacing current_trigger_context with None, a new event or an
unmarked captured context does not clear it. The flag carries no hidden reference
or payload; it is a conservative rejection condition, not capture introspection.

This closes a bounded hole in the current-context-only guard: a registered raw
callback or returned Effect callback can capture an unmarked context before a
later projection obligation, then run under an unmarked caller. The shared check
now rejects that body before reads, mutations or captured-context restoration.
External prototype selection/decline wrappers also consult this check, so a false
CapturedReadObligation snapshot cannot override the later world obligation.
Those external wrappers remain uninstalled in production.

All guarded unknown callbacks in such a world reject. This is deliberately not
a new admission rule, nor a certificate allowing a callback to execute. Unknown
factory execution still occurs before returned callbacks are wrapped, and public
callback replacement/direct unregistered readers can bypass those boundaries.
Factory origin must be proved from audited structured data, or unknown factories
must be rejected before execution. A DSL type/registry label alone is insufficient
because DslCardEffect::new_with_raw can carry arbitrary raw declarative factories.

Whole-Game reconstruction/replacement, remaining native/direct readers, structured
resume/decline/recovery/after-selection paths, compiler direct facts and transitive
safety, and whole-request rejection are still open. The private world bit does not
prove those transfers, useful projected execution, or full software qualification.
No historical request, model, search or scored launch follows from these tests.


## World-only Game factory entry rejection

The three Game entry methods effects_for_card, registry_effects and
effects_for_card_owned now check the inactive world obligation before under-top
lookup, cache access or factory invocation. Every factory origin remains
unproved: there is no trusted-type, card-ID or empty-result exemption. Cached
metadata also rejects because its construction may have used opaque captures.
Ordinary worlds retain their existing output and cache behavior, including None
for missing entries. A world carrying the obligation rejects even an absent
lookup request until a narrower factory-origin proof exists.

This factory check deliberately requires the WORLD bit. Context-only markers
retain their existing callback guards and do not by themselves reject factory
construction. No production world setter or projector is enabled. The unchanged
factory boundary tests continue to check context-only callback rejection.

A compiled DslCardEffect label is insufficient: new_with_raw can supply a raw
declarative factory that reads captured state while producing metadata, before
any returned callback could guard it. The new tests exercise this actual path,
as well as empty/metadata-only native factories, cached/uncached known/unknown
lookups, both seats and Game clones. This is pre-body rejection for the named
Game entry paths, not audited safe factory execution or complete admission.

Direct external factory objects, greedy policy's direct registry effects call,
Partition metadata delegation, direct keyword constructors and public callback
replacement remain outside these entry checks. Source inventories are not
semantic reachability proofs. Compiler-owned origin, all remaining readers and
transfers, and whole-request abort still require proof before qualification.

The greedy policy's card_has_resource_flow fallback now checks the inactive

Direct retained factory objects, public callback replacement, native readers,

## Bound compiled factory construction origin (not admission)

CardEffectRegistry now stores the wrapped factory and optional structured origin
in one private entry. The crate-private insert_compiled constructor creates the
actual DslCardEffect itself and binds its exact Arc<CompiledCard> and
Arc<EngineRawRustRegistry> inputs. Registration does not execute the factory.
The production DSL registration helper uses this constructor. Public insert
always clears the origin, including when its supplied object is a DslCardEffect.
Clones preserve the existing entry/factory Arcs; replacing one registry entry
cannot relabel a retained factory or change a sibling clone. Caller-side
Arc::make_mut changes fork the data instead of altering the registered inputs.

This is only a construction fact. It does not prove that CompiledCard originated
from a validated pack, that its clauses are safe, or that the raw registry has no
opaque captures. The record retains additional Arcs to inputs already held by
the actual factory; it stores no new Game or TriggerContext snapshot. All world
factory gates and returned-callback guards remain in force, including for these
recorded origins. No production consumer uses the origin query for admission.

Future proofs must bind any permission to the exact factory/cache generation,
not combine a current key's origin with a previously fetched Arc or cached
metadata. Raw declarations, runtime steps/formulas, native keyword construction,
all context transfers and whole-request abort still require separate proof.
No trusted origin, compiler safety certificate or projector is enabled here.


## Direct raw declarative construction facts

The bound compiled origin can now report ordered direct RawRust declarative
factory lookup requests. Each record contains clause region (card, Digimon face,
Option face), local clause index, function name, and membership in the bound
raw registry's declarative namespace. Missing names remain visible; duplicates
are preserved. Step/formula namespace membership cannot satisfy a declarative
request. Collection performs lookup only and retains no callback payload.

The traversal follows effects() construction order, including present dual data
even for manually supplied inconsistent card-kind IR. The clause enum matches
are exhaustive so new variants require reviewing these direct facts. This is
not a claim that other lowering helpers are pure or that every raw runtime
reference has been inventoried. A local clause index is not a flattened effect
slot or shared-OPT offset. No admission consumer uses these facts.

Behavioral fixtures compare facts against actual factory call order and show
that empty direct facts can still contain an opaque captured runtime step. Such
an ordinary step changes memory; the inactive world obligation still rejects
its callback before the body. Caller copy-on-write registration and replacement
do not alter an older bound origin or retained factory. Empty direct facts are
NOT safe projected execution, direct context liveness or transitive safety.

The list is structural and conservative: an earlier callback panic or lowering
failure can prevent later listed requests from being reached. Tests compare
actual order on the bounded fixtures, not all possible factory behaviors.
