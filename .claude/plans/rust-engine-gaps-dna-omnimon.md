# Rust engine gap-closure plan — DNA Omnimon

## Goal

Close the **62 🔴 BLOCKING + 6 🟡 PARTIAL** engine gaps (68 entries total) catalogued in `docs/RUST_ENGINE_GAPS.md` so that the DNA Omnimon archetype (64 unique cards, 3.5% meta share, 66 decklists as of 2026-04-04) can be fully implemented in `digimon-engine/` without stubs, approximations, or auto-selections (per CLAUDE.md §17–18).

Of the 6 partials, 3 are pure ergonomics/sugar (OPT recording helper, dual-timing builder, aggregate filter helpers) and 3 are primitives with a fidelity cost (native printed-keyword parsing, attack-without-suspending for MayAttack, if-effect-didn't-resolve else-branch). See the severity legend at the top of `RUST_ENGINE_GAPS.md`. Three additional items — Tamer play-from-security pipeline, multi-color Option match semantics, and conditional-inherited-DP-by-name — are listed in the "Deferred" section of that doc as test-coverage items, not engine gaps; they are out of scope for this plan.

This prompt was generated by `/assess-archetype-rust` on **2026-04-17**. Every cited gap title resolves to a section in `docs/RUST_ENGINE_GAPS.md`. If you revise card text, card pool, or engine API after that date, re-run `/assess-archetype-rust DNA Omnimon` before acting on this plan.

## Gaps to close (ordered by blast radius within each dependency tier)

The gap log is large but **highly connected** — most gaps cluster around ~8 structural primitives. Close the structural primitives first; the long tail of keyword/timing gaps drops into place once their dependencies land.

**Tier 1 — Foundational plumbing (touches every gap downstream):**
1. **Play card from hand without paying the cost** (🔴, ~16 cards) — single most load-bearing gap; `ctx.play_from_security` is the shape to generalize.
2. **Reveal top N cards of deck** + **Move revealed card to hand** + **Place revealed cards on deck top/bottom** (🔴 cluster, ~10 cards) — reveal pipeline.
3. **Return permanent to bottom of deck** + **Return permanent to hand** (🔴, ~13 cards combined) — zone-exit mutators.
4. **Move card from trash to hand** + **Trash from hand (by index)** (🔴, ~5 cards).
5. **Play card from digivolution sources (materials) without paying cost** + **Digivolution-stack reorder** (🔴, ~6 cards).
6. **Security-zone mutators:** place-permanent-to-security (top/bottom/face-up/face-down), add-top-security-to-hand, trash-opponent-security-top-N, Recovery-+N-from-deck, shuffle-security (🔴, ~7 cards combined).
7. **Observer/trigger context enrichment** (🔴, ~25 cards indirectly) — `EffectContext` fields `triggering_permanent` / `triggering_card` / `triggering_defender` / `leave_cause`, populated by `enqueue_triggered` at every firing site.
8. **EffectBuilder cost-payment hooks** — `.pay_cost_suspend_self()`, `.pay_cost_return_self_to_deck_bottom()`, generic `.pay_cost(|ctx| bool)` (🔴, ~12 cards combined).

## Ask

Produce a phased implementation plan (per `superpowers:writing-plans`) that:

1. **Groups gaps by subsystem**, preserving the 7-tier structure above. Do not attempt to close every gap in a single phase.
2. **Orders phases by dependency**. Tier 1 (foundational plumbing) and the context-enrichment portion of Tier 1 must land before any observer-trigger work; BeforePayCost scanning before cost-reduction cards; Option persistent placement before Delay keyword; LeaveCause provenance before Ace Overflow / Decode / Partition; Evade-class replacement infra before EX5-015 cost-to-prevent-battle-deletion.
3. **Within each phase, lists:**
   - **API surface to add** (exact function signatures / enum variants / struct fields). Cite the Suggested API Shape lines in `docs/RUST_ENGINE_GAPS.md`.
   - **Tests to write FIRST** (TDD per CLAUDE.md §18) — name the `digimon-engine/tests/*.rs` file and the specific test case. Prefer adding to `tests/test_cards_behavioral.rs` for card-observable behaviors; use `tests/engine_core.rs` or a new test file for new subsystem pieces (Reveal/Decode/Evade/Raid interrupt).
   - **Affected Rust files** (by path, under `digimon-engine/src/`).
   - **Parity implications** — does this phase resolve or create a `docs/RUST_PYTHON_PARITY.md` entry? Which?
4. **Flags architectural gaps that deserve their own design spec** under `docs/superpowers/specs/` before implementation. Strong candidates (three of them together are the biggest architectural shifts):
   - **Replacement-effect infrastructure** — unifies Evade (Tier 5), Partition (Tier 5), Decode (Tier 6), WouldBeDeletedInBattle (Tier 6 EX5-015), WouldLeaveField (Tier 2). A principled "interrupt + prompt + cancel-or-redirect" state machine.
   - **Native keyword parsing + declarative aura registry** — unifies printed-keyword parsing (Tier 5), named-target aura (Tier 6), granted-ability registry (Tier 6), declarative-from-security (Tier 6), digivolution-stack name overlay (Tier 6). All need the same "query-time iteration over active effect sources, filtered by a predicate" machinery.
   - **BeforePayCost + play-without-cost pipeline** — touches `play_from_hand`, `digivolve_from_hand`, new `play_from_hand_free` / `play_from_trash_free` / `play_from_materials` helpers, alt-digivolve data channel, and the `.pay_cost(...)` builder hook. Needs a coherent design, not five ad-hoc additions.
5. **Prefers 5–7 phases with clear stop points** where a phase's primitives unblock a verifiable subset of cards. Suggested stop points:
   - End of Tier 1: `ST2-13 Hammer Spark` becomes fully implementable once Option play flow lands (Tier 6, deferred) — use AD1-019 + one vanilla-stats DNA-Omnimon card (e.g. EX4-003 Tsunomon inherited tested alone) as canaries.
   - End of Tier 2: BT14-001 Koromon (OnSecurityCheck), BT15-020 Gabumon (StartOfYourMainPhase), BT5-093 Tai Kamiya & Matt Ishida's start-of-turn clause become implementable.
   - End of Tier 3: BT22-013 WarGreymon, BT17-015 WarGreymon, BT17-027 MetalGarurumon, ST20-10 Agumon implementable.
   - End of Tier 4: EX4-038 Agumon + BT12-059 Agumon + most reveal-and-search Options (still blocked on Option flow).
   - End of Tier 5 + 6: full 59-card BLOCKED tranche unblocked.
6. **Does NOT include card-script authoring.** That is the job of the forthcoming `/batch-implement-cards-rust` skill, once this engine work lands.
